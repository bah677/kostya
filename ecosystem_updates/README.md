# Обновления экосистемы (updates.mironbot.ru)

Публичный сайт: что изменилось **для пользователей**. Без миграций, .env и техдолга.

## Черновик (пока кодим на dev)

Пиши в `inbox/YYYY-MM-DD.md` (дата МСК) или сразу в `notes/` — но **не** запускай `publish.sh` сам.

Для отдельного продукта (например контент-аватар Юлии): `projects/<slug>/inbox/YYYY-MM-DD.md` → страница `https://updates.mironbot.ru/<slug>/`.

Тон: как для участников клуба. Не «готовится инфраструктура», а что человек увидит и как этим пользоваться. За день — один связный текст, при новых правках **переписывай файл целиком**.

Каждое user-facing изменение дня должно попасть в текст, **даже без ТЗ**. Блок **«ТЗ за день»** в конце — только если в этот день пометили ТЗ реализованными; иначе блок не нужен, текст апдейта всё равно пишем.

## Публикация (только после успешного деплоя)

`./scripts/deploy_prod.sh` в club / biblia / avatar / agency вызывает `publish.sh`:

1. переносит сегодняшний `inbox/YYYY-MM-DD.md` → `notes/` (если есть);
2. пересобирает `site/*.html`.

Вручную `publish.sh` — только чтобы починить сайт после ошибки, не как финал кодинга.

Отключить хук: `SKIP_ECOSYSTEM_UPDATES=1`.
