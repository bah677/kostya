# Черновики поддержки: справка из кода, FAQ и петля правок

Правки внесены в **DEV**. На прод уходят обычным `scripts/deploy_prod.sh` —
он же применит миграцию `040`.

## Что было не так

Разбор семи последних обращений (20–21 октября) показал три разных дефекта,
и два из них были записаны прямо в системный промпт.

**1. Шпаргалка по боту разошлась с ботом.** В промпте значилось

```
- оплата подписки: /menu → Оплатить подписку;
- подарок продления другому участнику: /menu → Подарить продление;
```

а кнопки называются «💳 Оплата и тарифы» и «🎁 Подарить продление в Клубе».
Пунктов из промпта в боте нет. Модель не выдумывала — она добросовестно
повторяла неверную справку, и люди шли искать несуществующие пункты.

**2. Промпт сам требовал отписок.** Строка

```
- если проблема техническая — назови причину из контекста (если есть) и шаги: /start, повторить, подождать;
```

давала «отправьте /start, подождите 10–15 минут и повторите» в четырёх
черновиках из семи. Человеку с отклонённой иностранной картой ждать
пятнадцать минут бессмысленно.

**3. На вопрос без ответа в справке модель отвечала наугад.** Один участник
дважды спросил про архив записей — и получил два взаимоисключающих черновика
(«архив в меню» и «архив в закрытой группе, а не в меню») с разницей в шесть
минут. Правильного ответа в системе нет: ни пункта меню, ни темы «архив» в
конфиге группы не существует.

## Что сделано

### Справка собирается из кода

`bot/services/support_bot_reference.py` строит блок «Справка по боту» из тех же
констант, что рисуют меню (`bot.texts.ru_user_menu`), и из каталога команд
(`bot.texts.help_catalog`). Переименуют кнопку — справка поедет следом сама,
руками её больше не ведут.

Там же `find_invented_menu_paths()`: ищет в черновике пути вида «/menu → X»,
которых в боте нет. Сравнение по словам без эмодзи и регистра, поэтому
неточная, но узнаваемая подпись («Подарить продление» вместо «🎁 Подарить
продление в Клубе») проходит, а выдуманная — нет. Черновик с выдуманным путём
бракуется и перегенерируется.

### Промпт переписан

Убрана инструкция про «/start, повторить, подождать». Вместо неё:

* **причина важнее ритуала** — если причина видна в логах, назови её; если нет,
  так и скажи, а не предлагай перезапуск ради заполнения ответа;
* **пути только из справки** — чего в справке нет, того в боте нет; вместо
  выдуманного пути честное «уточню и вернусь»;
* **не спрашивай то, что уже знаешь** — номер заказа, сумма, время попытки уже
  лежат в выдержке логов, незачем просить их у человека;
* **что делает поддержка, а что человек** — расчистить зависшую запись, сверить
  заказ, перенести оплату на другого участника человек не может, это наша
  работа; нельзя поручать её тому, кто уже написал, что у него не выходит;
* **про деньги** — если платёж отклонил банк, не отправлять «попробуйте той же
  картой ещё раз».

### FAQ из одобренных ответов

Таблица `support_faq`. Когда админ отправляет ответ по тикету, пара
«обращение → ответ» ложится туда автоматически — отдельной работы не нужно.
Источник различается:

| source | когда |
|---|---|
| `draft_sent` | админ отправил черновик как есть — значит, модель ответила верно |
| `admin_reply` | админ написал свой текст — значит, черновик был не тот |
| `manual` | занесено руками |

При генерации следующего черновика `find_support_faq()` достаёт похожие записи
по ключевым словам обращения и кладёт их в промпт блоком «ОДОБРЕННЫЕ ОТВЕТЫ».
Полнотекстовый поиск тут избыточен: записей будут десятки.

Так ответ на повторяющийся вопрос перестаёт сочиняться заново. История с
архивом, где один человек получил два разных ответа, после первого же
отправленного админом ответа повториться не сможет.

### Петля правок черновика

Reply на сообщение с черновиком:

```
/fix не предлагай перезапуск, у человека карта не из РФ
```

Модель переписывает черновик с учётом замечания и обновляет то же сообщение.
Предыдущие правки по этому тикету тоже уходят в запрос — иначе вторая правка
откатывала бы первую.

**Замечания работают и за пределами тикета.** Они копятся в
`support_draft_revisions`, и `recent_support_draft_instructions()` подаёт
свежие в промпт всех новых черновиков блоком «ЗАМЕЧАНИЯ АДМИНОВ». Повторяющуюся
претензию не придётся диктовать каждый раз: сказали один раз — модель учитывает
дальше сама.

Остальные способы ответить сохранились без изменений:

| действие | что делает |
|---|---|
| **✅ Отправить черновик** | отправляет как есть, тикет закрывается |
| **🔄 Заново** | генерирует черновик с нуля |
| **🔒 Закрыть без ответа** | закрывает тикет, пользователю ничего не уходит |
| Reply своим текстом | отправляет ваш текст вместо черновика |
| Reply `/fix …` | переписать черновик |
| Reply `/close` | то же, что кнопка закрытия |

### Закрытие без ответа

Раньше тикет закрывался **только** через отправку ответа. Если админ разобрался
с человеком в личке, закрыть тикет было нечем — он оставался висеть. Отсюда
часть из 151 открытого обращения.

Теперь есть кнопка «🔒 Закрыть без ответа» и `/close` в reply.
`update_ticket_status_only()` меняет статус, не трогая `admin_response`, и
ничего не отправляет пользователю.

## Чего это не чинит

Два вопроса остаются без правильного ответа, и никакой промпт их не закроет —
нужен ответ от вас:

1. **Где лежит архив записей эфиров для участников.** В коде клуба такого
   раздела нет. Полные записи аватар выкладывает в RAG-/админ-чат, а не в
   группу участников.
2. **Как платить иностранной картой.** Валютный тариф (15 USD) в боте есть,
   провайдер карту отклоняет. Либо настраивать приём таких карт, либо убирать
   тупиковую кнопку и давать человеку рабочий путь.

Как только ответы появятся — их достаточно один раз отправить по тикету, и они
сами попадут в `support_faq`.
