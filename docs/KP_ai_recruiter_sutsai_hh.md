# Коммерческое предложение

**Продукт:** ИИ-агент подбора персонала

## 1. Задача, которую закрываем

ИИ-агент:

1. сам ходит в HeadHunter по заданным правилам;
2. отсекает лишних по понятным триггерам (профессия, возраст, регион и т.д.);
3. через Сюцай раскладывает оставшихся по пригодности к **этой** должности;
4. отдаёт контакты на обзвон и карту человека — кто он и почему подходит или нет.

Сервис работает **поверх кабинета HeadHunter заказчика**. Агент использует официальный API-доступ работодателя.

---

## 2. Логика продукта в трёх этапах


|                             |                                                                                                     |                                      |
| --------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------ |
| Этап                        | Что умеет система                                                                                   | Для кого результат                   |
| **1. Поиск и отбор**        | Задания агенту, фильтр HH, скоринг Сюцай, контакты на обзвон                                        | Рекрутер / руководитель              |
| **2. Коммуникация и слот**  | Голос и переписка с кандидатом, слоты собеседований, календарь руководителя, подтверждение накануне | Рекрутер снимается с рутины дозвона  |
| **3. Введение в должность** | Память агента: навыки роли, документы и стандарты компании, сопровождение новичка                   | Руководитель после выхода сотрудника |


В этом предложении **фиксируется только Этап 1**. Этапы 2 и 3 описаны рамкой, чтобы было видно, куда растёт продукт; состав, сроки и стоимость по ним требуют отдельного согласования.

## 3. Этап 1. Функциональность

### 3.1. Подключение HeadHunter

- Используем офицальный API [hh.ru](http://hh.ru)  

- Можно:
  - взять **уже размещённые** вакансии из кабинета HH;  

  - описать **профиль вакансии** в агенте (роль, задачи, кого ищем, стоп-факторы) и привязать к вакансии HH.  

- Поиск резюме идёт через **официальный API**, в рамках услуг, уже оплаченных заказчиком на HeadHunter.

### 3.2. Задания ИИ-агенту

Агент — не чат «поспрашивать», а исполнитель с расписанием.

Пользователь ставит задание, например:

> Искать маркетолога, 25–40 лет, Москва и МО, опыт от 2 лет. Прогонять каждый день. В топ — кто ближе к профилю вакансии по Сюцай.

В задании задаются **триггеры**. Базовый набор Этапа 1:


|                    |                                                                             |
| ------------------ | --------------------------------------------------------------------------- |
| Триггер            | Как понимаем                                                                |
| Профессия / роль   | Образование по профилю **или** ищет эту профессию **или** уже работал в ней |
| Возраст            | Диапазон                                                                    |
| Регион / город     | Как в HH                                                                    |
| Ключевые слова     | ключевые слова для поиска                                                   |
| Занятость и график | По полям HH, если заданы                                                    |


Задание можно запустить сразу и поставить на регулярный прогон (например, ежедневно). Агент сам забирает новые и обновлённые резюме, не требуя каждый раз нажимать «найти».

### 3.3. Отбор и ранжирование

Скоринг строится от профиля Сюцай. Дата рождения кандидата для этого обязательна. Согласно официальному описанию API [hh.ru](http://hh.ru), дата рождения — это параметр, который может быть получен. Остаётся до конца не ясно, расходует ли это лимит на запрос контактов кандидата.

Цепочка по каждому человеку:

1. **Жёсткий фильтр** в HH по триггерам задания.
2. Запрос в Сюцай по ФИО и дате рождения: подробный профиль в рабочих срезах (мотивация, стиль, риски роли, предрасположенность к типу деятельности).
3. Сверка профиля Сюцай и резюме с профилем **этой** вакансии.
4. Кандидат встаёт в одну из трёх корзин — **высокий приоритет / средний / низкий**.

Выдача — упорядоченный список, а не «ещё 200 ссылок из HH».

### 3.4. Карточка кандидата для руководителя

По человеку из топа руководитель видит:

- сжатое резюме (роль, опыт, ключевые факты);  

- **Профиль Сюцай** — кто человек в рабочей реальности и насколько роль ему родственна;  

- почему агент поставил такой приоритет;  

- Ссылка на резюме

### 3.5. Результат прогона для рекрутера

- пачка на обзвон: ФИО, телефон / e-mail, ссылка на HH, приоритет;  

- кратко: сколько новых, сколько уже видели, сколько открыли контактов;  

- задание можно остановить, сузить триггеры, перезапустить.  


На Этапе 1 агент **не звонит и не пишет** кандидату сам. Он готовит очередь человеку.

## 4. Этап 1. Критерии приёмки

Приёмка — пилот на **одном кабинете HH** заказчика и **1–2 реальных вакансиях**. Считаем сданым, если выполнено всё ниже.

### HeadHunter

- Кабинет HH связывается через официальный OAuth  

- Список вакансий работодателя подтягивается из HH.  

- Триггеры профессии, возраста и региона реально сужают выдачу HH (проверка на тестовом задании).

### Агент и ранжирование

- Задание создаётся, запускается сразу и по расписанию (минимум: ежедневный прогон).  

- По итогам прогона есть три корзины: высокий / средний / низкий приоритет — на основании Сюцай и профиля вакансии.  

- У каждого кандидата в выдаче есть матрица Сюцай по этой вакансии (не общий текст «про всех с такой датой») и видно, почему такой приоритет.

### Интерфейс и отчёт

- Рекрутер в Telegram ставит задание, смотрит выдачу и забирает контакты на обзвон.  

- По прогону приходит отчёт: новые / повторные / открытые контакты / ошибки HH (лимит, нет услуги, истёк токен).

## 8. Этап 2. Коммуникация и слот собеседования *(рамка)*

Когда отбор уже даёт очередь, агент берёт на себя первый контакт.

- Голосовой и текстовый ИИ-агент пишет / звонит кандидату **от имени работодателя**.  

- Отправляет профиль должности и коротко — о компании.  

- Ведёт переписку, отвечает на типовые вопросы, предлагает слоты.  

- Слоты берутся из окон, которые руководитель заранее выделил в **Google Календаре**.  

- Встреча ставится в календарь руководителя.  

- Накануне — короткое подтверждение с кандидатом: придёт / не придёт / перенос.  


---

## 9. Этап 3. Введение в должность *(рамка)*

Когда человек принят, тот же контур не бросает его на пороге.

- У агента появляется память по роли: навыки, документы, стандарты, регламенты компании.  

- Новичок и руководитель получают сопровождение первых недель: что изучить, как ставить задачи именно этому человеку, где типичные разрывы.  

- Опора — профиль Сюцай сотрудника плюс база знаний компании.  


Это уже не рекрутинг, а адаптация. Детали и оценка — после Этапа 2.
